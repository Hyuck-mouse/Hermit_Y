# 服务端请求伪造 (SSRF)

## 描述
利用服务器发起请求的能力，访问内网资源、读取本地文件或攻击内部服务。

## 触发条件
- 功能如“抓取外部URL”、“获取远程图片”、“Webhook”等，用户可提供URL参数。

## 检测方法
1. **测试外网访问**：提供 `http://httpbin.org/get`，观察响应是否包含请求信息。
2. **测试内网**：提供 `http://127.0.0.1:80`，观察响应是否返回内网内容。

## 利用方式
- **读取本地文件**：使用 `file:///etc/passwd`（需协议支持）。
- **端口扫描**：尝试 `http://127.0.0.1:端口`，根据响应时间或状态判断端口开放情况。
- **攻击内网服务**：如 Redis（`gopher://127.0.0.1:6379/_*1%0d%0a...`）、MySQL、Elasticsearch。
- **利用AWS Metadata**：`http://169.254.169.254/latest/meta-data/` 获取云服务器信息。

## 绕过技巧
- **进制IP**：`127.0.0.1` → `2130706433`（十进制）、`0x7f000001`（十六进制）、`0177.0.0.1`（八进制）。
- **域名解析绕过**：使用 `http://localhost` 或 `http://0`。
- **URL编码**：`http://127.0.0.1%23@evil.com` 可能被解析为访问 `127.0.0.1`。
- **利用 `@` 符号**：`http://evil.com@127.0.0.1`，服务端可能忽略前面的域名。
- **利用DNS重绑定**：将域名解析到内网IP（需要外部DNS可控）。

## 附加提示
- 某些语言限制协议（只允许 http/https），可尝试 `gopher`、`dict` 等协议。
- 若SSRF可回显，直接利用；若盲SSRF，可结合时间延迟或DNSLog确认。
